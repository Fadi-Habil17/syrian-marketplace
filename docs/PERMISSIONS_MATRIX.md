# Permissions matrix

All entries require an authenticated, permitted session except public browsing. Business roles retain the buyer column. Active workspace, object ownership, restrictions and current state are checked in addition to role. Admin is separately provisioned; an admin UI never bypasses domain guards. Same checks apply on web/mobile HTTP, WebSocket subscriptions and file downloads.

## Enforcement details

- Ownership is an SQL-filtered predicate plus a policy check, never a caller-provided owner ID. Commands lock and recheck ownership and active profile where state can change concurrently.
- Public hidden/archived/unpublished records return 404. Authenticated but forbidden actions return 403; for private record enumeration use 404 consistently. Completed historical orders remain readable by their original participants after profile archival.
- Assigned drivers lose room and download access on reassignment, completion or restriction; after completion they retain redacted own payout/delivery history. Public job offers expose city/area, package summary and fee, not exact address/contact.
- An admin can view the case queue, take an audited assignment and then read its private chat/evidence. Account/catalog moderation and financial decisions are separate capabilities, assigned to the admin role in MVP but checked independently for later restriction.
- Both parties can submit evidence for 72h from case creation; system and handling admins append immutable notes. Submitted shared evidence is visible to the opposing party; internal moderation notes and security data are admin-only. Sensitive evidence submitted privately requires explicit visibility metadata and an audited access path.
- Suspended/restricted participants retain a controlled evidence/support route; ordinary purchasing, publishing, socket presence and funding obey the current restriction. Revoking a session or role terminates its active socket grants.
- Mobile push contains minimal event identifiers; opening it triggers fresh server authorization. Never place tokens/private data into a deep link.
