# Order state machines and effects

Planned backend transition contract. Tables use persisted states, not client-settable strings. All commands validate actor, current version, role/ownership, server time and restrictions. `H` = held order funds, `R` = full or agreed refund, `N` = durable in-app + socket + mobile push notification for affected participants. Every accepted transition appends immutable timeline/audit and outbox in its transaction. A rejected command changes no state, inventory or financial balance. Inventory is **not applicable for every service transition**. Common interruptions below apply to both service workspaces and the store where specified.

## Freelance

| From -> to                                       | Initiator                                 | Preconditions                                                                         | Escrow / inventory / notifications                                  |
| ------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| DRAFT -> AWAITING_AGREEMENT                      | Buyer                                     | Published listing, snapshotted scope/total/currency/due date; not self-order          | H=0; N provider                                                     |
| AWAITING_AGREEMENT -> AWAITING_DEPOSIT           | Provider then buyer acceptance if changed | Both approve same scope/total; valid installments                                     | H=0; 48h funding deadline; N buyer with amount at risk              |
| AWAITING_AGREEMENT -> REJECTED                   | Either participant                        | No hold                                                                               | H=0; N both                                                         |
| AWAITING_AGREEMENT -> EXPIRED                    | Worker                                    | Default 72h unanswered agreement                                                      | H=0; N both                                                         |
| AWAITING_DEPOSIT -> DEPOSIT_HELD                 | Buyer                                     | Within 48h; unique successful deposit; sufficient wallet                              | Hold rounded 1/3; snapshot commission; N both                       |
| AWAITING_DEPOSIT -> EXPIRED                      | Worker                                    | 48h elapsed and no hold                                                               | Zero charge; release any reservation; N both                        |
| DEPOSIT_HELD -> IN_PROGRESS                      | Freelancer                                | Deposit held, agreed due date                                                         | No movement; N buyer                                                |
| IN_PROGRESS -> IN_PROGRESS                       | Freelancer                                | Progress/milestone update, no billing                                                 | No movement; N buyer                                                |
| IN_PROGRESS -> READY_FOR_FINAL_PAYMENT           | Freelancer                                | Documented readiness; no blocking case                                                | No movement; start 72h balance timer; N buyer                       |
| READY_FOR_FINAL_PAYMENT -> FULLY_FUNDED          | Buyer                                     | Balance pending, within window, no blocking case                                      | Hold exact remainder once; N provider/buyer                         |
| READY_FOR_FINAL_PAYMENT -> FINAL_PAYMENT_OVERDUE | Worker                                    | 72h elapsed, remainder unpaid                                                         | Keep deposit; gate finals; create one admin case; N both/admin      |
| FULLY_FUNDED -> DELIVERED                        | Freelancer                                | Final files uploaded/validated; both holds committed                                  | No movement; record deliveredAt + 72h; unlock buyer finals; N buyer |
| DELIVERED -> COMPLETED                           | Buyer or worker                           | Confirmation, or 72h elapsed after digital submission; fully funded; no case/revision | Settle once, commission on awarded service; N both                  |

## Professionals: entry paths

| From -> to                                                              | Initiator                                            | Preconditions                                                         | Escrow / inventory / notifications                   |
| ----------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------- |
| DRAFT -> BOOKING_REQUESTED                                              | Buyer                                                | Package, serviceable address and proposed slot                        | H=0; 72h response deadline; N professional           |
| BOOKING_REQUESTED -> AWAITING_DEPOSIT                                   | Professional                                         | Accept request AND confirm original schedule; reserve time atomically | H=0; agreed total; 48h deposit deadline; N buyer     |
| BOOKING_REQUESTED -> SCHEDULE_PROPOSED                                  | Professional                                         | Alternative valid slot proposed                                       | H=0; no payment allowed; 72h buyer response; N buyer |
| SCHEDULE_PROPOSED -> AWAITING_DEPOSIT                                   | Buyer                                                | Explicit acceptance of alternate schedule, slot free                  | H=0; reserve confirmed time; 48h funding; N both     |
| BOOKING_REQUESTED/SCHEDULE_PROPOSED -> REJECTED                         | Provider declines original / buyer declines proposed | No hold                                                               | Zero charge; release tentative time if any; N both   |
| DRAFT -> PENDING_QUOTE                                                  | Buyer                                                | Description/photos/location, eligible professional                    | H=0; 72h response deadline; N professional           |
| PENDING_QUOTE -> PENDING_QUOTE                                          | Both                                                 | Agree free inspection slot/response deadline explicitly               | H=0; preserve inspection history; N both             |
| PENDING_QUOTE -> QUOTE_SENT                                             | Professional                                         | Itemized quote, scope, due date, schedule, currency, sum valid        | H=0; 72h approval deadline; N buyer                  |
| QUOTE_SENT -> APPROVED                                                  | Buyer                                                | Approve exact immutable version, total and schedule                   | H=0; reserve time; N provider                        |
| APPROVED -> AWAITING_DEPOSIT                                            | System in same approval transaction                  | Approved version and reservation valid                                | H=0; record APPROVED timeline; 48h funding; N buyer  |
| PENDING_QUOTE/QUOTE_SENT -> REJECTED                                    | Provider declines request / buyer rejects quote      | No hold                                                               | Zero charge; release time; N both                    |
| BOOKING_REQUESTED/SCHEDULE_PROPOSED/PENDING_QUOTE/QUOTE_SENT -> EXPIRED | Worker                                               | Unanswered current actionable request at 72h                          | Zero charge; release time; N both                    |

APPROVED is a recorded transition in quote history; order approval and AWAITING_DEPOSIT commit together to avoid an unpayable intermediate order. Quote version acceptance is unique. The freelance 72h pre-agreement timeout is default D06/D07; the professional timeout is required.

## Professionals: funded flow

| From -> to                                       | Initiator       | Preconditions                                                                    | Escrow / inventory / notifications                      |
| ------------------------------------------------ | --------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------- |
| AWAITING_DEPOSIT -> DEPOSIT_HELD                 | Buyer           | Accepted confirmed booking or approved quote; within 48h                         | Hold rounded 1/3, snapshot rate; N both                 |
| AWAITING_DEPOSIT -> EXPIRED                      | Worker          | 48h without hold                                                                 | Zero charge; release reserved slot; N both              |
| DEPOSIT_HELD -> IN_PROGRESS                      | Professional    | Deposit held and agreed work begins                                              | No movement; keep time; N buyer                         |
| IN_PROGRESS -> EN_ROUTE                          | Professional    | Traveling to service location, valid scope                                       | No movement; N buyer                                    |
| IN_PROGRESS/EN_ROUTE -> ON_SITE                  | Professional    | At agreed location                                                               | No movement; N buyer                                    |
| IN_PROGRESS/ON_SITE -> READY_FOR_FINAL_PAYMENT   | Professional    | Documented completed readiness                                                   | No movement; start 72h final-payment timer; N buyer     |
| READY_FOR_FINAL_PAYMENT -> FULLY_FUNDED          | Buyer           | Remainder due, no case                                                           | Hold remainder once; N both                             |
| READY_FOR_FINAL_PAYMENT -> FINAL_PAYMENT_OVERDUE | Worker          | 72h unpaid                                                                       | Keep deposit; no handover; one admin case; N both/admin |
| FULLY_FUNDED -> DELIVERED                        | Professional    | On-site handover recorded after payment; supporting proof                        | No movement; deliveredAt + 72h; N buyer                 |
| DELIVERED -> COMPLETED                           | Buyer or worker | Buyer confirmation or 72h with documented handover; fully held; no case/revision | Settle once; release reservation; N both                |

Progress substatus never starts work without a deposit. En-route/on-site remain valid for shared cancellation/dispute checks. Physical handover without sufficient documentation requires buyer confirmation/admin, as with store delivery.

## Home Store and delivery

| From -> to                                                          | Initiator                                   | Preconditions                                                                                           | Escrow / inventory / notifications                                                                           |
| ------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| DRAFT -> PAID_IN_ESCROW                                             | Buyer                                       | One seller/currency, serviceable address, agreed quote/options/fee, stock and wallet sufficient         | Hold full items+fee and reserve stock atomically; snapshot rate; 24h seller deadline; N seller/buyer         |
| DRAFT -> DRAFT (failed attempt)                                     | Gateway/application                         | Insufficient funds or simulated failure                                                                 | No hold/reservation/state advance; record failure; N buyer                                                   |
| PAID_IN_ESCROW -> PREPARING                                         | Seller                                      | Accept within 24h, no cancellation already committed                                                    | H unchanged; keep reservation; N buyer                                                                       |
| PAID_IN_ESCROW -> REJECTED                                          | Seller                                      | Declines before acceptance                                                                              | Full refund incl. delivery, release stock; N buyer                                                           |
| PAID_IN_ESCROW -> REFUNDED                                          | Buyer or worker                             | Buyer cancels before acceptance OR 24h seller timeout                                                   | Full refund incl. fee, release stock; N both                                                                 |
| PREPARING -> READY_FOR_DELIVERY                                     | Seller                                      | Goods ready; method and terms known                                                                     | H unchanged; keep stock; N buyer, eligible drivers if platform                                               |
| READY_FOR_DELIVERY -> READY_FOR_DELIVERY                            | Seller                                      | Seller delivers OR request platform job; buyer approves any changed terms first                         | Explicit delta hold/refund only if approved total changes; no silent debit; N buyer/drivers                  |
| Delivery REQUESTED -> ASSIGNED                                      | Eligible driver                             | Ready job, coverage, active profile; no active assignment                                               | No movement; unique assignment; N seller/buyer/driver                                                        |
| Delivery ASSIGNED -> REQUESTED                                      | Driver/seller before pickup                 | Release assignment with reason; no custody yet                                                          | No movement; revoke grants; reoffer N eligible drivers                                                       |
| READY_FOR_DELIVERY -> OUT_FOR_DELIVERY; assignment -> PICKED_UP     | Assigned driver or seller for seller method | Pickup event recorded; seller method has seller pickup/departure record                                 | H unchanged; reserve remains until fulfillment; N buyer/seller                                               |
| OUT_FOR_DELIVERY -> DELIVERED; delivery -> DROPPED_OFF              | Assigned driver or seller                   | Recorded drop-off time/history/proof status                                                             | H unchanged; consume fulfilled reservation once; start 72h review; N buyer/seller                            |
| DELIVERED -> COMPLETED                                              | Buyer or worker                             | Explicit buyer confirmation OR 72h documented verified delivery; fully held; no open case/revision      | Settle seller items + seller/driver fee, commission excludes fee; N all                                      |
| DELIVERED -> DELIVERY_REVIEW_REQUIRED                               | Worker                                      | 72h elapsed without proof or buyer confirmation                                                         | Freeze/hold; create admin review; no payout; N buyer/seller/admin                                            |
| READY_FOR_DELIVERY -> READY_FOR_DELIVERY (exception)                | Seller/worker                               | Driver unavailable; notify/escalate at default 2h                                                       | Keep hold; offer seller same terms, buyer-approved reschedule, or full refund if unavailable; N buyer/seller |
| PREPARING/READY_FOR_DELIVERY/OUT_FOR_DELIVERY -> DELIVERY_EXCEPTION | Seller/driver/buyer report                  | Delay, failed pickup/drop-off, lost goods or custody issue                                              | Hold funds; record evidence; no automatic settlement; N all/admin when needed                                |
| DELIVERY_EXCEPTION -> READY_FOR_DELIVERY/OUT_FOR_DELIVERY           | Buyer + seller, admin for custody change    | Approved reschedule/remedy, unchanged or explicitly approved terms                                      | Hold unchanged unless approved adjustment; no duplicate reservation; N all                                   |
| DELIVERY_EXCEPTION -> REFUNDED                                      | Seller or admin according to case           | Fulfillment unavailable/seller-caused nondelivery, no governing dispute; otherwise resolve through case | Full refund default incl. fee; reconcile reusable/nonrestockable stock; N all                                |

Delivery is a child aggregate: job request may be recorded at checkout but cannot be accepted before order readiness. Only one active ASSIGNED/PICKED_UP assignment. Reassignment after pickup is an audited admin custody decision. Delivery exceptions have no automatic forfeiture or unapproved fee changes.

## Shared interruptions and resolution

| From -> to                                                | Initiator                                  | Preconditions                                                                       | Financial / inventory / scheduling / notification effects                                                                    |
| --------------------------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Service DEPOSIT_HELD -> CANCELLED                         | Buyer or provider                          | Work not started; no existing governing case                                        | Full H refund; release slot; N both                                                                                          |
| Any unfunded agreement -> CANCELLED                       | Either permitted participant               | No held funds                                                                       | Zero charge; release slot; N both                                                                                            |
| Working service or accepted store -> CANCELLATION_PENDING | Buyer                                      | Work started or seller accepted                                                     | Freeze H; record refund proposal; 72h agreement deadline; stock remains/reconcile on outcome; N seller                       |
| CANCELLATION_PENDING -> CANCELLED                         | Buyer AND seller                           | Same documented allocation accepted within 72h, valid held sum                      | Settle agreed refund/awards once; commission on eligible award only; reconcile stock/release slot; N both/driver if affected |
| CANCELLATION_PENDING -> DISPUTED                          | Either rejects or worker at 72h            | No mutual agreement                                                                 | H frozen; admin case/evidence deadlines; no automatic award; N both/admin                                                    |
| Active service -> REFUNDED                                | Provider                                   | Provider cancels; no governing dispute/accepted settlement                          | Refund H in full; release time; N buyer                                                                                      |
| Active service -> EXTENSION_PENDING                       | Either / worker flagging missed deadline   | Agreed due date missed                                                              | Keep H; offer extension/cancel; pause unsafe release; N both                                                                 |
| EXTENSION_PENDING -> prior working state                  | Buyer and provider                         | Explicit new due date approved                                                      | No money; reschedule slot if needed; N both                                                                                  |
| EXTENSION_PENDING -> REFUNDED                             | Buyer/provider                             | Cancellation uncontested                                                            | Refund H; release slot; N both                                                                                               |
| EXTENSION_PENDING -> DISPUTED                             | Provider contests refund                   | Substantiated work/delay claim recorded                                             | Freeze H; admin review; N both/admin                                                                                         |
| Accepted store -> REFUNDED                                | Seller                                     | Seller cancellation/nondelivery; no governing case                                  | Full H refund default; reconcile stock incl. nonrestockable; release driver; N all                                           |
| Any held, unsettled order -> DISPUTED                     | Buyer or provider; system case for overdue | After hold, before committed settlement; includes delivery-review/change request    | Freeze all held funds; suspend completion; preserve inventory/proof; 72h evidence for each party; N both/admin               |
| DISPUTED -> REVISION_IN_PROGRESS                          | Buyer and provider                         | Both approve documented revision scope/due date                                     | Retain holds, pause timer, no duplicate service installment; N both                                                          |
| REVISION_IN_PROGRESS -> READY_FOR_FINAL_PAYMENT           | Provider                                   | Documented readiness; balance still unfunded                                        | Start new balance window per recorded agreed plan; retain deposit; N buyer                                                   |
| REVISION_IN_PROGRESS -> FULLY_FUNDED -> DELIVERED         | Provider                                   | Already fully funded; resubmit validated files/handover                             | No new hold; fresh deliveredAt and 72h review; N buyer                                                                       |
| FINAL_PAYMENT_OVERDUE -> READY_FOR_FINAL_PAYMENT          | Handling admin + participants              | Explicit resumption/new deadline, case resolved without allocation; no settlement   | Deposit retained, no forfeiture; gates remain until balance; N both                                                          |
| DISPUTED/DELIVERY_REVIEW_REQUIRED -> RESOLVED             | Handling admin                             | Each party has received its 72h evidence window; reason + substantiated allocations | One atomic refund/seller net/driver/commission journal; stock reconciliation/time release as relevant; N all                 |
| RESOLVED -> COMPLETED / REFUNDED / CANCELLED              | System in resolution transaction           | Recorded resolution fulfillment outcome                                             | Terminal outcome chosen from actual fulfillment; no second payout; N included above                                          |
| DELIVERED -> COMPLETED                                    | Buyer                                      | Even unproven physical delivery explicitly confirmed; no unresolved case            | Eligible settlement once; no automatic bypass of open case; N all                                                            |
| Any terminal -> same terminal + SUPPORT_CASE              | Participant                                | Already settled                                                                     | Support only; no original journal replay/reversal; N handling admin                                                          |

## Worker eligibility and timer checklist

| Deadline                                  | From                              | Effect at/after deadline                                      | Unique operation                |
| ----------------------------------------- | --------------------------------- | ------------------------------------------------------------- | ------------------------------- |
| Professional unanswered request/quote 72h | Current actionable request sentAt | Expire free, release slot                                     | order + responseVersion         |
| Service deposit 48h                       | Agreement confirmedAt             | Close free, release slot                                      | order + depositDeadlineVersion  |
| Final balance reminders 24h/48h           | Documented readyAt                | Notify only if still unpaid                                   | order + readyVersion + reminder |
| Final balance 72h                         | Documented readyAt                | FINAL_PAYMENT_OVERDUE, retain deposit, one admin case         | order + readyVersion            |
| Store seller acceptance 24h               | First full hold committedAt       | Refund full, release reservations                             | order + acceptanceWindow        |
| Cancellation agreement 72h                | Proposal createdAt                | Admin review; hold frozen                                     | case + proposalVersion          |
| Evidence 72h each party                   | Case openedAt                     | Queue admin review; never auto-award                          | case + party + evidenceDeadline |
| Delivery review 72h                       | Most recent recorded deliveryAt   | Complete eligible verified order once, otherwise proof review | order + deliveryVersion         |

Server timestamps define the boundary: buyer funding/response is allowed strictly before `deadlineAt`; at or after it, expiry applies under lock. Confirmation/dispute can be accepted until settlement commits, including during a delayed worker run. On revision create a new delivery version; preserve old timestamps and jobs, whose stale versions safely no-op. Recheck case/revision/paused/proof/funding and unique settlement IN the same transaction; dispatching a due job never grants unconditional release.
