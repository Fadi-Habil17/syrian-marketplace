## Findings corrected before merge

| Finding                                                                                   | Correction                                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Delayed refresh could restore credentials after logout or erase a later account           | Session-generation checks, serialized credential writes, discard responses from a previous session and remount scoped UI on account changes                                                                   |
| Authenticated auth/me skipped refresh; late 401s triggered unnecessary rotation           | Exclude only public auth operations; retry with the current access token when rotation already succeeded                                                                                                      |
| Store checkout could lose its key on re-preview/navigation/restart and fund another order | Persist only per-user command identity (draft ID, original version and idempotency key) before sending a hold; block a different draft until the outcome is resolved; never persist authoritative money/state |
| Permanent financial rejections trapped deposit/balance retries on a cached failure        | Retire the key only for definitive 4xx rejection; retain it on transport/server failure, authentication/rate-limit uncertainty and in-progress/conflicting intents                                            |
| Cart mixed-store validation threw inside React's state updater                            | Validate synchronously for the caller's error UI, with a pure updater recheck                                                                                                                                 |
| Every socket failure rotated credentials and a disposed socket could reconnect            | Refresh only AUTH_REQUIRED, once per connection attempt; prevent reconnect after cleanup                                                                                                                      |
| Arabic labels were literal question marks or mojibake                                     | Restore affected order, listing and delivery labels; remove environment-template BOM                                                                                                                          |
| Existing driver/admin/address/seller/push screens had no account navigation               | Add links to existing screens, explicit opt-in push and a back control; no new backend permissions                                                                                                            |
| Notification mutation errors became unhandled rejections                                  | Show failure and disable repeated in-flight actions                                                                                                                                                           |
| Mobile tests were absent from CI                                                          | Add `npm run test:mobile` to the existing workflow                                                                                                                                                            |

Checkout persistence is a retry record, not a new payment workflow. A successful response removes it; a confirmed rejection permits a new attempt. Uncertain outcomes keep the same intent even after restart, isolated by user. Storage failure stops checkout before a payment request. Native SecureStore behavior still requires device acceptance; unit tests exercise the adapter boundary.
