# UI upgrade verification — 24 November 2026

This report covers the landing, authentication and appearance increment on `feat/sheam-ui-appearance`, based on `33b41e45d7581abf91868833300f25fb3cc9861d`. It supplements, rather than replaces, the backend/security and first-release reports. It does **not** certify the unfinished mobile administration, all business journeys, production delivery or B4F submission.

**Outcome:** final web acceptance **PASS** (64 cases); normal Android auth/appearance **PASS**; Android font-configuration → appearance **FAIL / High UI-01**; iOS runtime **BLOCKED**. This is not release approval.

Status meanings: **PASS** = actually executed successfully; **FAIL** = reproduced failure; **BLOCKED** = required environment/asset unavailable; **NOT RUN** = not executed in this increment.

## Implementation

- Responsive original landing using the existing green/cream/gold palette, actual discovery routes and three supported workspaces. Localized search is primary. No invented catalog responses, reviews or activity counts.
- Keyboard/touch journey tabs and meaningful step previews. Service copy retains one-third funding followed by the remainder; store copy retains full checkout. Backend amounts, order states and permissions remain authoritative.
- Shared visual auth identity: compact native/narrow forms and a bounded desktop form beside a local photo story. Persistent labels, accessible errors, show/hide password, native autofill metadata and clear pending/success states use existing auth endpoints and sessions.
- Light/Dark/System tokens applied through web globals and native shared primitives, navigation, auth, catalog, workspace/admin forms and dialogs. Preferences persist locally. Web applies saved appearance before the body renders. Native holds the launch screen until fonts and stored appearance are ready; stack backgrounds and system bars use the selected palette.
- Original silent working-app walkthrough, captions and poster-first deferred playback. Marketplace film uses the permitted nonplayable fallback pending approved footage. See [media plan](ui-upgrade/MEDIA_PLAN.md).

## Failures observed and disposition

No failed run was silently counted as a pass:

1. Initial axe scan found three low-contrast journey step numbers. Removing opacity fixed their contrast; all 36 final layout/axe cases passed.
2. First TypeScript iteration rejected a native conditional style union. Using an explicit boolean fixed it. ESLint's raw image warning was fixed with the existing Next Image component and optimized local poster.
3. Real Android screenshots revealed the brand SVG incorrectly tinted into a solid square and navigation icons too dark. The multicolor brand keeps its original artwork; navigation symbols now use the semantic action color.
4. Initial web runner reported five failures: its init script overwrote the saved preference at every navigation, and cookie assertions ran before the redirected response finished. The runner now initializes storage only once and waits for the actual authenticated heading/cookie. All five affected cases then passed, followed by the complete 50-case pass. Session cookie security was not weakened.
5. A test initially assumed Arabic would use a particular digit system. The runtime locale determines its digits; the corrected locale-aware assertion passed. A build helper was also invoked from the wrong working directory; that command failed visibly, then the correct final source was copied and rebuilt successfully.
6. A capture started before the test server was ready and received connection refused. Added readiness polling and reran the complete after measurement successfully.
7. Expo Go initially failed to download its development update while Metro restarted. Reopening after server readiness loaded the real bundle. An asynchronous Android activity launch also caused a harness restart failure; synchronous `am start -W` passed. Neither was hidden as application acceptance.
8. Native harness assumptions were corrected: logout returns to the market, and the Arabic name field is labelled “الاسم”. A wrong expected label/route is retained as a failed attempt, not an app defect. The final account/logout, Arabic auth and accessibility phases passed.
9. A concurrent diagnostic accessibility dump interrupted one Android runner (exit 137). Further native UI work was serialized, bounded snapshot retries report interruptions, and the authenticated account/logout check passed.
10. The first native scroll helper swiped over the keyboard, and a Back assertion omitted Android’s keyboard dismissal. It now uses observed ScrollView bounds and dismisses the keyboard before testing route Back.
11. Changing Android font scale recreated Expo Go, briefly displayed its launch screen and reopened home. Startup release now also handles activation/font changes. The test waits for ready content and explicitly reopens auth before measuring 200% text. Final login/register/keyboard screenshots and the accessibility case passed; standalone-binary configuration/navigation restoration remains untested.
12. Sandboxed Node tests initially failed with child-process `EPERM`. Rerunning with allowed process execution produced 15/15 web and 22/22 mobile passes, with no skipped tests.

## Remaining reproduced defect — UI-01 (High)

**FAIL:** Android Expo Go can show `Unable to find viewState for tag … Surface stopped: false` when appearance is changed after a system font-scale/activity recreation. This was reproduced on the named Pixel_7_Pro emulator and prebuilt Expo Go 54.0.8 with SDK 54 / project React Native 0.81.5 New Architecture. See the [failure screenshot](ui-upgrade/failures/android-font-theme-fabric.png) and [failed case](ui-upgrade/results/android-font-theme.json). Font scale is restored to 1.0 after the test.

Reproduction: launch signed-out Arabic auth; select Light; change emulator font scale to 1.5; reopen the auth development URL after Expo Go recreates its activity; select Dark and apply. The native Fabric mounting error prevents further UI use until reload/restart. All four normal login permutations and 200% auth layout/keyboard checks passed separately; this configuration-then-theme case is **not** covered by those passes.

Separating preference application from modal dismissal, removing forced native UI-mode changes, an app-surface overlay experiment, stable native navigator props and noncollapsable roots did **not** establish a fix. The experimental overlay was removed; the final client retains the simpler appearance dialog, explicit app tokens and themed payment confirmations. No native exception was suppressed and no dependency/engine migration is claimed. A [React Native upstream issue](https://github.com/react/react-native/issues/49077) describes the same error family; that similarity does not prove this app has an identical root cause or a verified upstream fix.

Android configuration/appearance acceptance remains **FAIL**. A standalone development/release binary and physical-device reproduction are **BLOCKED** on that environment; current Expo Go results cannot certify them. Investigate a compatible native-runtime fix with a standalone build before release.
