# REST and WebSocket contracts

This document defines conventions and a **planned** resource inventory. Initial executable API exposes only `GET /api/v1/health`; Swagger at `/api/docs`, OpenAPI JSON at `/api/docs-json`. Do not connect clients to planned business endpoints until the slice's OpenAPI request/response/error examples are reviewed and generated types plus Postman are committed.

## Transport and representations

- HTTPS in deployment; `/api/v1` version prefix, plural resource names, UTF-8 JSON. UTC RFC3339 timestamps; server timestamps/deadlines authoritative. Locale `ar`/`en` with explicit response language; catalog fields preserve both languages. Enum values remain stable English identifiers.
- UUID IDs; amounts `{ "currency": "SYP", "units": "101" }` or USD units in cents; never JSON BigInt/float. Rates are integer `basisPoints`. Clients format currencies, never recalculate the amount to authorize.
- Success returns resource JSON, no redundant envelope. Lists: `{ "items": [], "nextCursor": null }`; opaque cursor, `limit` 20 default, 100 maximum, stable `(createdAt,id)` ordering. Validate workspace-specific filters/category/location/price/rating/delivery days; cursor includes filter/order signature.
- POST create 201; synchronous commands 200, accepted async file scan 202; empty delete/deactivation response 204. REST commands use intent endpoints, never accept arbitrary `state`/`balance` patches. Include `version`/`If-Match` on state-changing commands; stale version 409.
- Shared error shape: `{ "error": { "code": "INSUFFICIENT_FUNDS", "message": "...", "details": [], "requestId": "..." } }`. Translate stable error codes on clients; no secrets/stack traces. Validation field errors use property/code, not raw input values. Initial infrastructure has no failing domain routes yet; implement the exception mapper before auth slices.

## Authentication and retries

Passport JWT bearer for mobile/API; web server-only client forwards short-lived access token from HttpOnly session. CSRF/Origin checks guard web cookie mutations. Refresh rotates the hashed refresh session and detects reuse. Do not accept admin role/business ownership from client-controlled claims without current database checks. Server DTO validation uses whitelist + forbidNonWhitelisted + transform with explicit conversions.

Financial commands, checkout, delivery acceptance, dispute resolution and other externally retried commands require `Idempotency-Key` (UUID recommended). Scope key to actor+route; store a canonical validated request hash and completed response. Same key/body returns the same result, including insufficient-funds failure. Same key/different body => 409. An in-progress duplicate returns 409 REQUEST_IN_PROGRESS with Retry-After; client retries same key. New payment attempt after a recorded failure uses a new key. Unique order installment/settlement keys also prevent duplicate effects across DIFFERENT client keys. A timeout means unknown result: query operation status or retry same key, never assume failure and create another charge. Permanent financial operation keys outlive HTTP key retention. Serialization retries preserve the key and check current eligibility; max three immediate retries, then 503 safe retry.

## WebSocket contract (planned)

Socket.IO namespace `/orders`, version `1`. Browser uses a short-lived single-use ticket from `/realtime/ticket`; mobile uses access JWT. Authenticate handshake and authorize every join/message/attachment. Leave/revoke on session/participant/assignment change. Never emit a whole private order to a public job room.

Client sends `order.subscribe { orderId, lastSeenVersion }`, `order.unsubscribe { orderId }`, `chat.send { roomId, clientMessageId, text, attachmentIds }`, and `notification.ack { notificationId }`. Every command has ack `{ ok, data?, error?, requestId }`; sending a message invokes the same application command as REST, deduped by sender/room/clientMessageId. Payment and administrative decisions remain explicit REST commands.

Server envelope `{ eventId, type, version: 1, aggregateId, aggregateVersion, occurredAt, data }`:

| Event                  | Data                                                              | Audience                                                     |
| ---------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------ |
| `order.updated`        | state, deadlineAt, safe progress                                  | Buyer/provider; driver receives delivery-filtered equivalent |
| `payment.updated`      | operationId, status, installment, currency, units, simulated=true | Order buyer/provider; private wallet details excluded        |
| `chat.message.created` | roomId, messageId, senderId                                       | Authorized members of that room only                         |
| `delivery.updated`     | deliveryId, status, proofAvailable                                | Buyer/seller/current driver                                  |
| `driver.job.available` | jobId, coarse area, currency, feeUnits                            | Eligible coverage room, no private contact/address           |
| `case.updated`         | caseId, status, evidenceDeadlineAt                                | Parties and handling admins                                  |
| `notification.created` | notificationId, category, resourceId                              | Recipient user room                                          |
| `permissions.revoked`  | roomId, reasonCode                                                | Actor losing a grant; disconnect/clear cache                 |

Committed outbox events can arrive more than once or out of order. Deduplicate by eventId and ignore older aggregateVersion; refetch on a gap. Reconnect requests authorized history via REST (socket does not promise replay). Socket upload bytes and continuous location streaming are out of scope. Rate-limit sends/joins and cap event size at 32 KiB; files travel through Files endpoints.
